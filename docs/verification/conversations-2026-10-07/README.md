# 会话面板重构验收（2026-10-07）

## 最终布局与功能边界

- 左上角菜单打开会话与全局菜单面板；手机从底部滑入，宽度达到 600px 时改为居中淡入，最大宽度 640px。
- 面板顶部保留 nanobot 品牌、新建话题和搜索入口；会话列表独立滚动，全局设置与连接状态固定在底部，设置项不混入会话列表。
- 全局设置仍仅包含主题、语言和退出。右上角 Chat options 继续负责当前会话的模型、工作区和权限，没有新增重复入口。
- 沿用 nanobot 的分组、项目、置顶、归档、重命名、删除保护及接口；不引入 OpenMuse 的 Main chat／Side chats 业务区分、数据模型或 API。
- 删除旧 SidebarDrawer 及其样式，将 UI 导航命名统一为 conversations，不保留旧抽屉兼容分支；sidebar 领域的 store／hooks 名称继续保留。
- 打开与关闭面板不重置聊天草稿；实际新建或切换会话才沿用原来的聊天重置流程。
- Android 返回优先退出重命名或会话／项目操作子层，再关闭面板。真实软键盘先按系统规则收起。
- 键盘避让后测量内部可用高度，限制面板高度，避免 Android 重命名表单被挤出屏幕。顶部短横条仅为装饰，不实现拖拽关闭。
- 聊天页、会话面板、搜索与操作层沿用聊天调色板；认证和全局设置保持共享调色板。没有新增依赖或修改网关配置。

## Android 模拟器实测

使用现有开发客户端与 Metro 加载本轮代码，没有重复配置 JDK／Android 环境，也没有修改服务端会话数据。

已实测：

- 左上角打开底部面板，显示真实会话列表及 Connected 状态，关闭按钮正常。
- 专用未发送草稿在面板开关后保留。
- 会话操作菜单、重命名表单打开及取消正常；最终键盘布局下，表单标题、输入框、取消和保存按钮完整可见。
- Android 返回先收起键盘，再关闭重命名子层，面板仍保留。
- 搜索能过滤真实会话；选择结果后搜索关闭，聊天标题更新为选中的会话。

没有在真实后端执行置顶、归档、重命名保存或删除。新建回调、归档显示、深色主题、iOS／宽屏布局由自动测试覆盖，本轮没有对应设备实测。无障碍子层隔离属性已由 Native 测试覆盖，但没有做 TalkBack 实测。

测试后重启应用并回到空白聊天；没有留下测试草稿或改变本地主题／语言。

### 待排查：长历史加载 ANR

在 Android 模拟器从搜索选中一条较长历史会话后，出现系统“应用无响应”提示。不能将该场景计为通过。

- 输入焦点事件等待约 5 秒后触发 ANR。
- 原生主线程堆栈位于 `TextView.onMeasure` → `StaticLayout` → React Native `CustomLineHeightSpan.chooseHeight`，表明当时正在执行文本排版。
- 日志同时出现 VirtualizedList 大列表更新慢的警告。
- 当前证据不足以确定具体根因，也尚未证明与本次会话面板改造的因果关系。本次提交未混入未经验证的消息渲染／分页性能改造；该风险仍待单独排查。

原始日志、ANR 堆栈及界面抓取仅保留在被忽略的 `.local/verification-raw/conversations-2026-10-07/`，不提交设备原始诊断数据。
